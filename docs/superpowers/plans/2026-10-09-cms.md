# Vietverse CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin biên tập, xem trước và xuất bản bài học/truyện/văn hóa; nhập nội dung khách hàng đã gửi mà không mất lịch sử học tập.

**Architecture:** Giữ ba collection live, thêm draft độc lập và snapshot published bất biến. Client và API học dùng cùng contentVersion; publish dùng MongoDB transaction. Bộ nhập nguồn đã biết tạo draft có nguồn gốc, không ghi đè live hoặc bản admin đang sửa.

**Tech Stack:** TypeScript, Express, Mongoose 8, Zod 3, React 18, React Query 5, Zustand, Vitest, Testing Library, Supertest, MongoMemoryReplSet.

**Spec:** `docs/superpowers/specs/2026-10-09-cms-design.md` (bản sửa tại commit `380ee71`).

**Trạng thái:** Người dùng đã duyệt tiếp tục thực hiện ngày 2026-10-09; đang triển khai trực tiếp (Native). Nhật ký kiểm chứng được ghi theo từng task, chưa nhập database production.

## Shared Contracts

Định nghĩa tại Task 1, dùng đúng tên trong các task sau. ID trong DTO là string, Date là ISO string; không đưa Mongoose Document vào client.

```ts
type ContentKind = 'lesson' | 'story' | 'culture';
type FieldIssue = { field: string; message: string };
type SourceRef = {
  documentUrl: string; tabId: string; heading: string;
  capturedAt: string; checksum: string;
};
type EditorialNote = {
  field: string;
  reason: 'missing_source' | 'unsupported_activity' | 'variant' | 'attribution';
  message: string;
};
type ContentPayloadMap = {
  lesson: LessonContent;
  story: StoryContent;
  culture: CultureContent;
};
type DraftView<K extends ContentKind> = {
  kind: K; contentId: string; payload: ContentPayloadMap[K];
  draftVersion: number; baseContentVersion: number | null;
  state: 'editing' | 'synced' | 'discarded';
  updatedAt: string; updatedBy: string;
  source?: SourceRef; editorialNotes: EditorialNote[];
};
type PublishedView<K extends ContentKind> = {
  kind: K; contentId: string; contentVersion: number;
  payload: ContentPayloadMap[K];
};
type PublishInput = {
  expectedDraftVersion: number; baseContentVersion: number | null;
};
type PublishReceipt = {
  contentId: string; contentVersion: number; publishedAt: string;
};
```

`LessonContent` whitelist: stageId, order, title, description, vocabulary, activities, freeInStarterPlan, totalActivities. `StoryContent`: type, title, author, description, coverImage, lyrics, audioUrl, durationSec, ageGroups, vocab, quiz. `CultureContent`: category, title, intro, coverImage, funFacts, quiz, audioUrl, tags. Reuse structures in existing models, but normalize ObjectIds and strip subdocument `_id` in DTO. Draft permits empty values/arrays; missing UI fields receive empty defaults, never invented content. Keep unknown legacy category visible until admin deliberately corrects it. totalActivities is derived, not editable.

  if (!value) return true;
  if (value.startsWith('/') && !value.startsWith('//') && !value.includes('\\')) return true;

    const url = new URL(value);
    return url.protocol === 'https:' && !url.username && !url.password;
